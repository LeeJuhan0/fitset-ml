## Naming Conventions

### 함수명 (소문자 + 밑줄)

```python
# Correct
def get_text()

# Wrong
def get_Text()
def Get_Text()
def Get_text()
```

### 변수명 (소문자 + 밑줄)

```python
# Correct
text
text_length

# Wrong
Text
text_Length
Text_length
```

### 전역변수명 (g + 밑줄 + 변수명)

```python
# Correct
g_text
g_text_length

# Wrong
G_text
g_Text_length
g_text_Length
```

### 모듈명 (소문자 + 밑줄)

```python
# Correct
dataset.py
text_style.py

# Wrong
Dataset.py
text_Style.py
```

### 클래스명 (대문자 시작 및 대문자로 단어 구분)

```python
# Correct
class VideoCapture()
class VideoWriter()

# Wrong
class videoCapture()
class Video_writer()
```

### 상수명 (모두 대문자 사용 + 밑줄)

```python
# Correct
PATH
WINDOW_SIZE

# Wrong
Path
window_SIZE
```

# Correct

## Imports

import 줄에 한개의 모듈 또는 라이브러리 임포트하기

```python
# Correct:
import os
import sys

# Wrong
import sys, os
```

하지만 from 사용시 여러가지 모듈 또는 라이브러리 사용가능

```python
# Correct
from subprocess import Popen, PIPE
```

## 표현식, 조건식의 공백

### (), [], {} 안에 공백 최소화

```python
# Correct
spam(ham[1], {egg: 2})

# Wrong
spam( ham[ 1 ], { eggs: 2} )
```

### ,와 닫는 괄호( ")" ) 사이 공백 최소화

```python
# Correct:
foo = (0,)

# Wrong
bar = (0, )
```

### ,와 ; 그리고 : 사이 공백 최소화

```python
# Correct
if x == 4: print x, y; x, y = y, x

# Wrong
if x == 4 : print x , y ; x , y = y , x
```

### 예외

```python
# Correct
ham[1:9], ham[1:9:3], ham[:9:3], ham[1::3], ham[1:9:]
ham[lower:upper], ham[lower:upper:], ham[lower::step]
ham[lower+offset : upper+offset]
ham[: upper_fn(x) : step_fn(x)], ham[:: step_fn(x)]
ham[lower + offset : upper + offset]

# Wrong
ham[lower + offset:upper + offset]
ham[1: 9], ham[1 :9], ham[1:9 :3]
ham[lower : : upper]
ham[ : upper]
```

### 열린 괄호 ( "(" ) 전에 함수 또는 리스트 사이 공백 최소화

```python
# Correct:
spam(1)

# Wrong:
spam (1)
```

### 열린 괄호 ( "[" ) 전에 함수 또는 리스트 사이 공백 최소화

```python
# Correct:
dct['key'] = lst[index]

# Wrong:
dct ['key'] = lst [index]
```

### "=" 연산자 사용 후 숫자 또는 문자열 정렬을 위한 최대 공백은 1칸

```python
# Correct:
x = 1
y = 2
long_variable = 3

# Wrong:
x             = 1
y             = 2
long_variable = 3
```

### 바이너리 연산자 사용 전&후 1칸 공백 사용

계산해야하는 우선순위가 높은 숫자 또는 변수 사이의 공백은 최소화 되어야한다.

```python
# Correct:
i = i + 1
submitted += 1
x = x*2 - 1
hypot2 = x*x + y*y
c = (a+b) * (a-b)

# Wrong:
i=i+1
submitted +=1
x = x * 2 - 1
hypot2 = x * x + y * y
c = (a + b) * (a - b)
```

## 함수 공백

### 함수의 인자값 또는 반환값에 쓰이는 "=" 연산자 뒤로 공백은 필요없음

```python
# Correct:
def complex(real, imag=0.0):
    return magic(r=real, i=imag)

# Wrong:
def complex(real, imag = 0.0):
    return magic(r = real, i = imag)
```

### 조건문 이후 다음 줄에 함수 호출

```python
# Correct:
if foo == 'blah':
    do_blah_thing()

# Wrong 1:
if foo == 'blah': do_blah_thing()

# Wrong 2:
if foo == 'blah': do_blah_thing()
for x in lst: total += x
while t < 10: t = delay()

# Wrong 3:
if foo == 'blah': do_blah_thing()
else: do_non_blah_thing()
try: something()
finally: cleanup()
do_one(); do_two(); do_three(long, argument,
                             list, like, this)
if foo == 'blah': one(); two(); three()
```

### 동일한 줄에 여러개 함수 호출하지 않음

```python
# Correct
do_one()
do_two()
do_three()

# Wrong
do_one(); do_two(); do_three()
```

## 반환문

함수의 끝에 (도달 가능한 경우) 명시적인 반환문을 추가해야 합니다

```python
# Correct:
def foo(x):
    if x >= 0:
        return math.sqrt(x)
    else:
        return None

def bar(x):
    if x < 0:
        return None
    return math.sqrt(x)

# Wrong:
def foo(x):
    if x >= 0:
        return math.sqrt(x)

def bar(x):
    if x < 0:
        return
    return math.sqrt(x)
```

## 객체 유형 비교

객체 유형 비교 시에는 유형을 직접 비교하는 대신 항상 isinstance() 메서드를 사용해야 합니다.

```python
# Correct:
if isinstance(obj, int):

# Wrong:
if type(obj) is type(1):
```

## Pydantic

요청·응답 데이터 모델은 Pydantic을 최대한 사용하고, 응답도 response_model을 사용해야 합니다.

- 타입 검사가 자동으로 이루어짐
- Swagger UI에서 요청·응답 스키마를 확인할 수 있음 (협업용)
- 자동 데이터 필터링 (response_model에 정의된 필드만 응답에 포함됨)

```python
# Correct:
class UserResponse(BaseModel):
    id: int
    name: str

@router.get("/users/{user_id}", response_model=UserResponse)
def get_user(user_id: int):
    return service.get_user(user_id)

# Wrong:
@router.get("/users/{user_id}")
def get_user(user_id: int):
    return {"id": 1, "name": "juhan", "password": "..."}   # 검증·필터링 없이 dict 그대로 반환
```

## 응답 봉투(Envelope) 패턴

모든 API 응답은 성공·실패 관계없이 동일한 봉투 형태 `{success, code, message, data}`를 사용해야 합니다.

- 성공: `success=true`, `data`에 결과 (라우터의 response_model=Envelope[...]가 검증)
- 실패: `success=false`, `message`에 사유, `data`는 부가정보(없으면 null)
- 실패 변환은 라우터마다 하지 않고 전역 예외 핸들러(main.py)가 담당 — HTTP 상태코드는 그대로 유지
- 클라이언트가 성공/실패를 한 가지 파싱 로직으로 처리할 수 있게 하는 것이 목적

```python
# Correct:
# 성공 응답 — {"success": true, "code": "200", "message": "...", "data": {...}}
# 실패 응답 — {"success": false, "code": "404", "message": "배포된 모델이 없습니다.", "data": null}
@app.exception_handler(StarletteHTTPException)
async def http_exception_handler(request, exc):
    return JSONResponse(
        status_code=exc.status_code,
        content={"success": False, "code": str(exc.status_code), "message": str(exc.detail), "data": None},
    )

# Wrong:
# 성공은 봉투인데 실패는 FastAPI 기본 포맷 그대로 — {"detail": "..."}
# (클라이언트가 성공/실패 파싱 로직을 두 갈래로 가져야 함)
```
